# 清理功能如何判斷與處理檔案

這份文件寫給第一次使用磁碟透視、沒有參與開發的人。它說明安全清理頁面會處理什麼、哪些資料需要使用者決定，以及清理後的容量數字該怎麼看。

一鍵清理使用可追查的本機規則，沒有呼叫雲端人工智慧服務逐檔判斷，也不會把掃描結果上傳給這類服務。

## 一鍵安全清理會做什麼

按下「一鍵清理」後，磁碟透視會先重新掃描，再直接移除符合規則的舊快取與舊診斷。快取通常可以重新下載或產生；舊診斷無法重建，清除後會失去那份除錯歷史。這裡只處理已知位置中符合期限與檢查條件的檔案，不把整個快取資料夾視為可刪除。

這裡的「套件」是開發工具下載的程式元件。套件下載快取保存下載或編譯的副本；專案套件則是某個專案實際使用的元件，兩者的整理方式不同。

表中的目錄檢查，會讀取已知快取資料夾中的內容，排除原始碼與模型等資料，再核對檔案類型及使用者要求保留的位置。掃描有數量與深度上限，超過上限或無法讀完就保留；實際位置與上限列在附錄。自動處理的項目有三類：

| 類型 | 必須符合的條件 | 清理後的影響 |
|---|---|---|
| 已知程式快取 | 能辨識所屬程式、程式目前未執行、檔案至少一天未修改；所在目錄通過上述檢查 | 下次使用可能重新建立快取，首次載入較慢 |
| 套件下載快取 | 位於明確指定的下載快取位置，至少三十天未修改，通過同樣的檔案與保護檢查 | 已安裝套件保留；未來安裝可能需要重新下載或編譯 |
| 舊診斷紀錄 | 位於目前帳號的診斷紀錄目錄，屬於指定紀錄類型，至少三十天未修改 | 無法再回看這份舊診斷，不影響原始文件 |

按下「一鍵清理」後，程式會重新掃描並立即處理符合規則的項目，不另開逐檔確認視窗。想先看內容，可以使用旁邊的「先查看可清項目」。之後再按一鍵清理仍會重新掃描，所以檔案有變動時，實際處理清單可能與先前預覽不同；判斷規則保持一致。

這些檔案直接移除，不經垃圾桶。程式會在按鈕旁說明這件事，也提供「先查看可清項目」。私人文件、一般下載、專案套件和程式移除，都有另外的整理入口。

「一天」和「三十天」是本版採用的保留期限，目的是保留近期變動的資料。程式判斷的是最後修改時間，不能把它解讀成最後開啟時間。

## 為什麼有些快取會保留

名稱像快取，不足以證明內容可重建。磁碟透視先確認位置，再檢查裡面的項目。如果發現原始碼、研究資料、模型或專案標記，整組會退出自動清理。內容過多、過深或讀取不完整時，也會保留，交由使用者檢視。

程式只移除掃描時已記錄、清理前仍符合條件的普通檔案。符號連結，以及同一個檔案同時有多個名稱的情況，會先保留。尚未下載的雲端內容，以及不屬於目前帳號的檔案，都不會加入這份自動清單。清理期間新出現的檔案不會被順便刪掉；資料夾本身也會保留。

掃描結果分成「可一鍵清理」「請你確認」「已保留」「讀取受限」。尚未確認的資料不會計入一鍵清理容量。「已保留」仍能檢視原因，但無法在這份結果中勾選移除；若是使用者自己加入的保留設定，可以先移出保留清單再重新掃描。權限不足也不會被寫成零容量，讓使用者誤以為已經掃完。

## 需要使用者決定的五種整理

這五個工具都先掃描、顯示原因，再讓使用者選取。送出後還有確認畫面，符合條件的項目會移到 Finder 垃圾桶。

### 專案建置資料

磁碟透視會讀取專案設定，尋找下載的套件與建置輸出。單靠資料夾名稱相同，不會提出清理建議。下載套件必須有版本鎖定資料，也就是記錄各元件確切版本的專案設定；一般編譯輸出則必須有對應的專案設定。部分常見輸出目前刻意不辨識，避免把私人資料誤認成產物。

程式會檢查是否夾帶手寫原始碼或另一份版本管理資料；無法完整排除時保留。執行前也會檢查是否有目前帳號的程式正在該專案目錄工作。這只能偵測一部分使用情況，因此仍需要使用者確認已停止建置與相關工作。

重新安裝或建置可能耗時，也可能需要網路。直接修改過下載套件內容的人，應先保存修改；版本鎖定資料只能協助重新取得版本，無法還原私人修改。共用開發環境、虛擬環境與版本管理目錄不列為專案垃圾。

### 安裝檔整理

工具尋找七天以上未修改的安裝檔、磁碟映像，以及一天以上未修改的未完成下載。這些日期只用來縮小整理範圍，不能證明檔案已經無用。需要離線安裝、保存舊版或繼續下載的人可以保留。

### 大型與舊檔案

工具列出內容大小達一百兆位元組（本版門檻為 104,857,600 位元組），或至少一百八十天未修改的一般檔案。這是整理提示，不是垃圾判定。檔案即使很久沒改，也可能是需要長期保存的論文、照片或封存資料。

### 重複檔案

工具先依大小分組，再比較檔案前後片段，最後完整讀取內容比對。只有完整內容一致，才列為重複副本。每組會指定一份保留檔，其餘副本預設不勾選。

執行前會再次比對副本和保留檔；保留檔消失、內容變動，或也被選入移除範圍時，會停止處理該副本。內容相同的檔案仍可能有不同標籤、權限或用途，工具不會自動合併這些資訊。

### 程式與關聯資料

程式本體和設定、快取、離線資料分開列出，全部預設不勾選。關聯資料只能依程式識別名稱或固定、已知的位置對應，不採用程式顯示名稱來猜測。這可避免重新命名程式後，把另一個同名資料夾當成其資料。

同一程式仍有其他安裝副本、其他程式內含同一程式，或安裝清單讀取不完整時，關聯資料會保留。系統程式、磁碟透視本身及執行中的程式也會保留。共享容器、鑰匙圈與系統服務不會根據名稱猜測後移除。

選取關聯資料可能移走設定、登入狀態與離線文件。只想卸載程式本體時，不需要選取這些資料。這個工具沒有宣稱能卸載每種需要專用卸載器或背景服務的軟體。

## 保留清單和清理前檢查

使用者可以在結果上按右鍵，選擇「加入保留清單」，並在保留清單中管理。設定在本機保存，會套用到新掃描及清理前檢查；路徑中的中文與特殊字元會當成實際名稱處理。

共用開發環境是同時供多個工具使用的程式與套件安裝位置。Mole 是另一套 Mac 清理工具。磁碟透視也尊重本機既有的 Mole 保護清單。如果電腦有使用者自行維護的共用開發環境登錄表，也會保留其中記錄的執行環境位置；目前支援的登錄位置列在附錄。程式並內建保護重要設定、登入金鑰、模型與同步資料的位置。保護設定存在卻無法完整讀取時，程式會暫停可執行清理，避免在不知道使用者要求的情況下繼續。

掃描與執行之間，檔案可能已經變動。自動清理會核對檔案身分、大小、修改時間、擁有者與連結狀態，再逐檔處理；手動整理也會重新確認位置與原本的分類依據。這裡把一個快取資料夾，或一份診斷紀錄，稱為一組。程式會在自動清理各組開始前重讀保護設定，並在組內每十六個檔案再次檢查保護與所屬程式執行狀態。分批檢查是為了減少反覆讀取設定的成本；若程式在檢查間隔內啟動，最多可能還會處理這批剩餘的十六個檔案。這些檢查縮短變動到被偵測的時間，但不能把仍在寫入中的程式當成已停止；發現使用中狀態就保留剩餘項目。

同一時間只允許一個清理工作執行。任何一次清理結束後，前一次掃描結果都會失效；目前頁面會重新掃描，其他視窗必須重新掃描才能整理。其他視窗可能仍顯示舊結果，但再次執行時會被拒絕並提示重新掃描。這能避免兩個視窗各自移走同一組重複檔案的不同副本。

## 停止、失敗與還原

介面上的「停止」就是取消尚未開始的後續操作，已完成的移除會留在紀錄中。程式不會宣稱停止能撤銷已完成的直接移除。執行失敗或檔案已變動時，會保留項目並顯示原因；每組最多保存三十筆錯誤訊息，避免紀錄失控。

手動移動整個資料夾前，程式會重新檢查；如果在最後檢查後，其他程式才往裡面新增檔案，這些新內容仍可能一起移到垃圾桶。因此手動整理前應停止相關程式和工作；需要還原時，將整個資料夾搬回原位置。

如果檔案操作已成功，但本機紀錄無法保存，畫面仍會顯示實際成功數與保存失敗的提示。此時應先截圖保存畫面上的結果，再關閉頁面；關閉後可能無法從清理紀錄查到這次操作。重新掃描只能看見目前剩下的內容，無法還原已直接移除的檔案。

移到垃圾桶的項目可以從紀錄打開 Finder 查看，再使用 Finder 的還原功能。某些原本隱藏的資料夾會使用可見名稱放進垃圾桶；紀錄保留原位置，必要時依原位置手動搬回。磁碟透視目前沒有自動還原整批操作的功能。

舊診斷會直接移除，是本版為回收空間採用的保留期限政策；它們無法重新產生，因此與可重建快取的性質不同。需要留存除錯歷史的人應先保護此位置。

直接移除的舊暫存不能從垃圾桶取回；一般情況由原程式重新產生。需要保存舊診斷的人，應在一鍵清理前將該位置加入保留清單。

## 清理容量怎麼看

「直接清除」顯示已成功移除檔案的配置容量；配置容量是檔案在磁碟上配置的空間，可能與內容大小不同。「移到垃圾桶」顯示移走項目的容量，垃圾桶未清空前通常仍占磁碟空間。尚未量得容量的程式或資料夾會明確標示，並可在檢視畫面量測。

程式另行量測清理前後的系統可用空間。檔案系統快照、共享區塊、壓縮與其他程式同時寫入，都可能讓可用空間變化和移除量不同。因此，紀錄中的移走容量不能當成磁碟實際多出的空間。

## 既有進階規則的位置

舊版清理分類保留在「進階規則」。其中有由系統工具管理的快取、垃圾桶與外接磁碟整理等用途。這些操作沒有自動加入新版一鍵清理；進階頁面原有的預覽、確認與保護仍然適用。本文的一鍵規則，不能當作進階分類中每個項目都適合直接清除的保證。

## 附錄：可核對的規則與位置

以下是供開發者和進階使用者核對的實作細節。`~` 代表目前帳號的家目錄。

| 自動規則 | 位置／類型 | 限制 |
|---|---|---|
| 程式標準快取 | `~/Library/Caches/<bundle identifier>` | 僅程式內列出的固定 vendor ID；須找到已安裝 owner |
| 程式產生的快取 | `~/Library/Application Support/<固定 vendor folder 或 exact bundle ID>/{Cache,Code Cache,GPUCache,DawnCache,ShaderCache,GrShaderCache}` | 僅固定已知 app ID；不猜 CFBundleName；已知 Chromium profiles 與 Firefox cache2 另有固定規則 |
| npm | `~/.npm/_cacache` | 30 天；不處理 `_npx`、已安裝套件或專案依賴 |
| pip | `~/.cache/pip/{http-v2,wheels}`、`~/Library/Caches/pip/{http-v2,wheels}` | 30 天；不探索自訂 cache-dir，不刪 Python prefix、site-packages、venv |
| 診斷 | `~/Library/Logs/DiagnosticReports` 的直接普通檔案 | `.crash .ips .hang .spin .log`；30 天 |

已知程式完整 ID、固定 vendor folder 和快取標記列在 `SmartCleanupEngine.swift`、`CleanupApplicationCatalog.swift`，屬版本控制內容。單組自動快取最多走訪 100,000 個項目、深度 8；超過就改為人工檢視。這個上限不會截取前面一部分後自動刪除。

手動檔案掃描最多走訪 200,000 個項目、深度 12。專案目錄檢查最多 20,000 個項目；無法完整排除風險則保留。一般掃描略過 Library、Applications、隱藏目錄、版本管理、環境與套件目錄；專案模式會在辨識到產物後檢查該組。這些界線意味結果不是整台電腦的無限制完整盤點。

診斷紀錄的位置是 `~/Library/Logs/DiagnosticReports`。要保留整個診斷資料夾，可在「保留清單」選「新增位置」，並在系統選擇視窗使用前往資料夾功能輸入此位置。既有開發環境登錄表的支援位置為 `~/.config/python/environments.json`；程式只讀取 prefix 保留位置，不改動環境或登錄表。

保留設定為 `~/Library/Application Support/MacStorageLens/cleanup-protection.json`，清理紀錄在同目錄的 `Cleanup History/Workbench/`。它們含有本機路徑，留在本機，不應當作問題回報附件或開源範例直接上傳。

專案來源與擴充方式見 [清理開發說明](cleanup-development.md)，研究依據及未採用的做法見 [清理研究對照](cleanup-research.md)。
