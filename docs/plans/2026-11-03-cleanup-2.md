# 安全清理重做：2.0

這是開發前的計畫與設計審查紀錄。最終規則、實作限制與驗證範圍以[清理邏輯](../cleanup-logic.md)、[維護說明](../cleanup-development.md)及[版本說明](../release-notes/2.0.0.md)為準。舊診斷無法重建，不能將本文早期的「可重建」概括為全部自動清理項目。

後續需求已擴大為全軟體文案重整，並完成兩輪分區審查；總覽與資料樹保留功能，修正文字及即時容量來源綁定。

使用者要的是日常清理可以主要使用磁碟透視：主頁提供一鍵安全清理，軟體負責判斷可重建暫存；下載、專案、應用程式與大檔另有清楚的詳細整理。1.8.0 的保護與權限修正是基礎，不能視為已達成這個目標。總覽與資料樹維持現有行為。

## 本階段交付

1. 新智慧清理主頁：直接「一鍵安全清理」與只掃描預覽兩個入口；顯示可自動處理、需要確認、已保護／目前使用中及讀取受限的實際結果。以項目的可重建證據、擁有程式、執行狀態、位置及保護設定判斷，不以舊風險等級直接全選。
2. 自動處理限目前帳號、已知可重建快取及過期診斷檔；每次執行重新驗證。直接清除暫存的按鈕文字與說明必須明確。個人檔案、離線內容、開發環境、垃圾桶與程式卸載不混入自動清理。
3. 新詳細工具：依專案證據辨識可重建建置資料；遞迴找舊安裝檔；大檔與完整內容重複檔；已安裝程式及精確關聯資料的移除預覽。項目可搜尋、檢視完整路徑、查看判斷理由，逐項選擇。大型檔案不算垃圾，重複檔永遠保留一份、執行前重驗內容。
4. 手動整理預設進 Finder 垃圾桶，記錄可還原位置；自動暫存清理記錄完成、失敗、原先估算與執行後重查結果，不把垃圾桶移動量當成已釋放磁碟空間。掃描與長雜湊可取消；受限或截斷結果明確標示。
5. 重做清理頁，舊六級規則移至進階入口。採原生 SwiftUI、既有視覺語彙，主流程以一般使用者能判斷的文字呈現。所有使用者看得到的文案依「講人話」技能檢查。

這次範圍是清理流程與相關檔案／程式整理；掃毒、風扇、網路設定、RAM 清空與 App 更新器屬其他用途，不用來膨脹完成數。保留 macOS 14 與無外部 Swift 套件的架構。Python／Android 共用環境和既有 Mole 保護設定持續生效；不把虛擬環境當專案垃圾。

## 完成證據

- 實際比較舊版缺口，每項新能力都有來源與產品情境。
- 暫存目錄驗證：一鍵只移除符合證據的可重建資料；執行中、受保護、最近變動與偽造候選被拒絕；不同工具不重複計算同一路徑。
- 專案不只看名字；重複檔驗完整內容並排除硬連結、雲端未下載檔；程式移除不以公司名稱模糊推斷私人資料。
- 原生新介面可掃描、預覽、取消、查看理由與結果；實機只讀，刪除測試只使用暫存資料。
- 既有回歸、release build、獨立程式審查、安裝驗證及 GitHub 發布與公開來源包校驗完成後才報交付。

## 迭代檢查點

先完成來源比較與新流程的可執行骨架，確認核心是一鍵判斷與執行而非多一頁規則；再補齊詳細工具、測試與原生介面。時間先不估定，第一批可編譯功能完成後依實測調整。每個階段記錄已完成、缺口和下一個可驗證產物；不因一個模組或打包完成便宣稱完整取代其他軟體。

## 設計審查後的必要約束

獨立審查指出舊執行器會重列候選目錄當下全部內容，不能直接接一鍵全選。新一鍵流程必須凍結可處理的檔案清單與 device/inode、擁有者、大小、修改時間，逐檔重驗；掃描後新增的檔案不得被目錄整批移除。已知快取須能對應真正擁有程式，涵蓋 Support 路徑；未知／共享擁有關係降為確認。取消掃描不得進入自動執行。重複檔執行時重驗保留檔，且保留檔不得在另一個選取的父目錄內。巢狀 App 與同 ID 多份副本、共享容器須分辨；關聯資料預設不選，共享或歸屬不明保留。專案資料夾若含手寫來源、巢狀版本庫或屬已登錄環境，保留。
