# MacStorageLens 1.7.6 — 中文路徑與 UTF-8 相容性修正

## 修正

修正新掃描報告中的中文資料夾、其他 Unicode 名稱與完整路徑變成 `?`，造成資料樹、Sunburst、路徑導覽及 Finder 操作無法對應實際目錄的問題。

Scanner 原本以 `LC_ALL=C` 固定報告數字格式與路徑排序。在 macOS 27.2 實測，系統 `du` 在這個語系下會把中文名稱直接替換為問號，資料在進入報告解析器之前就已經丟失。本版只對輸出檔名的 `du` 呼叫指定 `en_US.UTF-8`，其餘報告處理維持原本的 C locale。

修正涵蓋一般與管理員掃描共用的核心、App TCC 使用者資料覆蓋，以及安全清理候選的容量讀取。管理員路徑在權限切換後指定 UTF-8，避免依賴 `sudo` 是否保留呼叫端語系。

另修正 macOS 27 SDK 搭配獨立 Command Line Tools 的建置相容性：以獨立名稱的 `LensState` alias 明確選用既有公開 `SwiftUI.State` property wrapper，保留原本初始化與 Binding 行為，避免誤選缺少 plugin 的新 `@State` macro。這項做法也適用舊 SDK；沒有新增套件或改用新的狀態模型。背景見 [SwiftUI State 相容性說明](https://docs.folivora.ai/docs/plugins/swift-source-plugins/#swiftui-state-with-command-line-tools)。

## 更新後請重新掃描

已經寫成問號的舊報告無法從問號反推出原始名稱。安裝新版後，請針對受影響位置執行新的完整掃描；原本磁碟中的資料夾名稱與檔案內容沒有被這個顯示問題修改。

既有 Markdown 報告格式、舊版報告解析與清理索引 schema 保持相容。舊的清理候選若受影響，請在安全清理頁選擇「完整重新掃描」，重新取得路徑與容量。

## 回歸測試

新增 `UnicodePathAudit.swift`：以真正的核心與監督器掃描暫存資料夾，經 `ReportParser` 讀回，檢查繁體中文、相同字數但不同名稱的目錄、中英混合、日文、emoji、組合字元、空格、引號與 `$`。另外透過安全清理的公開掃描入口檢查中文路徑容量；測試會確認 fixture 檔案內容未改變。

測試強制由 `LC_ALL=C` 的父程序啟動，避免測試依賴 Terminal 本身已有正確語系。既有 36 階段驗證入口加入這項測試，並繼續驗證原有清理政策、容量帳務、報告解析與 macOS release build。

- Unicode 端到端測試：48 / 48 通過。
- 本機外接磁碟完整掃描、中文深層路徑導航及真實報告容量 audit：通過。
- SwiftPM release build、App 封裝、ad-hoc 簽章驗證及啟動：通過；Mach-O 最低系統為 macOS 14。
- 原有 36 階段：27 項通過、8 個清理 fixture 未通過、1 項系統報告 audit 對此次外接磁碟報告不適用。建置仍有 Swift／linker 警告。

### 既有驗證限制

在本機 macOS 27.2 上，`FolderCleanupAudit`、`ExternalAppleDoubleCleanupAudit`、`ApplicationCacheCanonicalPathAudit`、`SystemJunkScannerFixtureAudit`、`SystemJunkDeveloperCacheFixtureAudit`、`SystemJunkLiveRevalidationAudit`、`SystemJunkDirectDeleteFixtureAudit`、`TrashBinsCleanupAudit` 仍未通過。

以上八項均已使用上一版公開的 1.7.5 source ZIP 重現相同失敗；前兩項的失敗檢查清單完全一致，其餘為相同的候選／前置條件失敗。最小案例也確認本機 Foundation 目錄列舉 API 會略過 `._` 名稱。原有驗證入口會在第 11 階段停止，本次另行執行後續階段收集完整結果；本版不宣稱整套清理驗收通過。詳細記錄見 [驗證說明](../VERIFICATION.md)。
