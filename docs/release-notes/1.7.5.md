# MacStorageLens 1.7.5 — 系統垃圾規則深度整合與廢紙簍

## 同一版本的介面修正

1.7.5 Build 32 雖然把規則與廢紙簍功能接進底層，卻又在安全清理頁加入版本專屬的大型「整併位置」卡片。那個設計把 release note 變成永久資訊架構，未來每次更新都可能繼續堆疊一次性區塊。Build 33 在不改變 1.7.5 功能範圍的前提下，撤回這個 UI，重新完成真正的產品整合。

## 新的清理頁資訊架構

- 六級 profile selector 是唯一入口，不新增第七種模式，也不新增版本專屬功能卡。
- 所選 profile 下方保留一個通用摘要；「掃描範圍與安全規則」會從 `CleanupScope.cases(for:)`、`minimumTier` 與目前模式動態產生。
- 選取 **超激進（L5）** 時，摘要內才顯示三項附加功能：高影響可回收資料、廢紙簍永久清空、系統管理項目（僅檢視）。
- 選取 **自定義** 時，才展開逐項 scope 開關與最低容量設定。
- MacSai 僅以一行低干擾來源說明出現在等級摘要底部；來源資訊不再主導版面。

這個結構沒有綁定 1.7.5。未來新增 `CleanupScope` 或調整 `minimumTier` 時，詳情區會沿用同一套模型，不需要再增加「1.7.6 規則位置」「1.7.7 規則位置」等遺留 UI。

## 六種操作模式

| 操作模式 | 實際內容 |
| --- | --- |
| 超級保守（L1） | 標準／沙盒／群組快取；Spotify offline 與 broad Gradle state 在 sizing 前排除。 |
| 保守（L2） | 剪貼簿暫存、App web/render cache、停滯 incomplete downloads。 |
| 平衡（L3） | Xcode、Cursor／Antigravity、Claude／Codex 與 package-manager 精確 cache allowlist。 |
| 激進（L4） | 嚴格 bundle-ID App leftovers、可證明損壞的第三方 plist、使用者 logs／diagnostics。 |
| 超激進（L5） | 基礎範圍加入舊 installer／disk image；高影響資料、system review 與廢紙簍永久清空在選取 L5 後以三個獨立、預設關閉的附加開關呈現。 |
| 自定義 | 所有 scope 各自開關；Trash scope 預設不會自動加入既有偏好。 |

## 廢紙簍的掃描範圍

1. 目前使用者 `~/.Trash`。
2. `/Volumes/<volume>/.Trashes/<目前 UID>`，但 `<volume>` 必須在執行時再次證明是本機、可寫、非內置、非 Time Machine 的真實外接卷宗 root。

不包含其他 UID、整棵 `.Trashes`、NAS／伺服器 `#recycle`、SMB／NFS／WebDAV／AFP／SSHFS 等遠端 mount、符號連結、特殊檔案、控制字元路徑，以及掃描後才新增但未列在候選中的項目。

## 執行語意

- Trash candidate 為 `permanentDeleteMatchedItems`，不能再移進 Finder Trash。
- 候選永遠預設未勾選，且 `requiresManualSelection == true`。
- 執行前重新驗證 root、精確 direct child、類型與 symlink 狀態。
- 逐項呼叫 `FileManager.removeItem`；部分失敗會留下逐項 failure，不會把整批冒充成功。
- 只刪除 matched items；`~/.Trash` 或 `.Trashes/<UID>` root 本身保留。
- 清理後使 Trash scope 失效，下一次補充掃描重新列舉。
